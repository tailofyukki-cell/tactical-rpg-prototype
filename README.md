# Gridbound Tactics Prototype

Windows 向け 2D タクティカル RPG の戦闘プロトタイプです。味方 3 人で特徴の異なる 9 マップを攻略し、位置取り、攻撃範囲、向き、地形、障害物、素早さ順の個別行動を検証できます。

現在のゲーム全体設計と実装状況は [現状設計書](docs/current-design.md) にまとめています。

## 起動

```powershell
cd C:\Users\konkon\tactical-rpg-prototype
npm start
```

ブラウザで `http://127.0.0.1:4174/` を開きます。Windows では `start-windows.bat` をダブルクリックしても起動できます。

## 簡易パッケージ作成

```powershell
npm run package
```

出力先:

```text
dist\GridboundTacticsPrototype
```

出力されたフォルダ内の `PLAY.bat` から起動できます。現段階ではブラウザ実行プロトタイプなので、完全な `.exe` 化は Godot 版またはデスクトップラッパー導入後に行います。

## 操作

- `MOVE`: 青い範囲から移動先をクリック
- `ATTACK`: 黄色い範囲内の敵をクリック
- `SKILL`: 物理スキルを選び、対象をクリック
- `MAGIC`: 攻撃魔法または回復魔法を選び、対象をクリック
- `ITEM`: ポーションで隣接した味方を回復
- `WAIT`: 待機して次の行動へ
- `TALK`: 街で選択中の NPC と会話
- `SHOP`: 街のショップへ移動
- `BUY`: ショップで選択中の商品を購入
- `INN`: 街の宿屋で HP / MP を全回復
- `CHAPTER`: 章選択へ移動
- `NEXT CHAPTER`: 解放済みの章を切り替え
- `DUNGEON`: ダンジョンルート選択へ移動
- `START`: ブリーフィングまたはダンジョン選択から戦闘開始
- `TRAIN`: レベルアップで得た SP を使ってスキルツリーを取得
- `PARTY`: 戦闘前またはリザルト後に育成画面を開く
- `NEXT UNIT`: 育成画面で表示キャラを切り替え
- `NEXT SKILL`: 育成画面でスキルツリー選択を移動
- `TRAIN SELECT`: 選択中のスキルツリーノードを取得
- `EQUIP WEAPON`: 育成画面で武器を切り替え
- `EQUIP ARMOR`: 育成画面で防具を切り替え
- `EQUIP ACC`: 育成画面でアクセサリーを切り替え
- `SAVE`: 現在の戦闘状態をブラウザのローカル保存へ記録
- `LOAD`: 保存した戦闘状態を復帰
- `SLOT 1/2/3`: 使用するセーブスロットを切り替え
- `RESTART`: 初期状態から再戦
- `Esc`: 移動先・対象選択をキャンセル
- `Enter`: シナリオ送り、街NPC会話、ショップ購入、ダンジョン開始、ブリーフィング開始

右パネルに行動順、ユニット情報、地形情報、ダメージ予測を表示します。

## データ追加

- `data/characters.json`: 味方・敵、初期位置、ステータス、成長率
- `data/weapons.json`: 武器攻撃力、射程、命中、射線
- `data/skills.json`: スキル、魔法、回復、範囲、MP 消費
- `data/items.json`: 戦闘アイテム
- `data/equipment.json`: 防具、アクセサリー、装備補正
- `data/skilltrees.json`: クラス別スキルツリー
- `data/progression.json`: EXP テーブル、初期所持金、装備インベントリ、武器熟練ランク補正
- `data/locations.json`: 街、NPC、宿屋、ダンジョンルート
- `data/shops.json`: ショップ在庫、価格、購入対象
- `data/chapters.json`: 章番号、想定時間、シナリオ、戦闘ルート、報酬、次章解放
- `data/maps.json`: ダンジョン別マップサイズ、タイル、障害物
- `data/terrain.json`: 地形移動コスト、防御、回避、通行可否
- `data/map.json`: タイル配置、障害物、勝敗条件
- `data/sprites.json`: キャラクター画像のパス、フレームサイズ、方向行
- `data/cutins.json`: スキル・魔法カットインの画像パス、色、表示時間

## シナリオ制作フロー

シナリオの正本は [docs/scenario-bible.md](C:/Users/konkon/tactical-rpg-prototype/docs/scenario-bible.md) です。

別チャットで世界観、章ごとの会話、キャラ設定を作る場合は、確定した内容だけを `docs/scenario-bible.md` に反映します。その後、実装用データとして `data/chapters.json` と `data/scenario.json` へ落とし込みます。

役割分担:

- `docs/scenario-bible.md`: 採用済みの設定、章構成、キャラ方針
- `data/chapters.json`: 章番号、想定時間、使用ルート、報酬、解放先
- `data/scenario.json`: 実際にゲーム内で表示する会話
- `data/locations.json`: 街、NPC、宿屋、ダンジョン導線

## キャラクター画像の差し替え

キャラ画像は `src/game.js` に直接書かず、`data/sprites.json` から読みます。

1. PNG を [assets/characters](C:/Users/konkon/tactical-rpg-prototype/assets/characters) に置く
2. `data/sprites.json` の `path` を画像ファイル名に合わせる
3. `data/characters.json` の各キャラの `sprite` に、`data/sprites.json` 側の ID を指定する

標準想定は 32x32 のスプライトシートです。

- 0 行目: 下向き
- 1 行目: 左向き
- 2 行目: 右向き
- 3 行目: 上向き
- 0 列目: 待機フレーム

画像がまだ無い場合は、自動で仮ドット表示に戻ります。フレームサイズや方向行は `data/sprites.json` の `defaults` または各キャラ定義で変更できます。

## カットイン画像の差し替え

`SKILL` と `MAGIC` 使用時に、短いカットインが入ります。画像が無い状態でもキャラ名と技名の演出が表示されます。

専用画像を使う場合:

1. PNG を [assets/cutins](C:/Users/konkon/tactical-rpg-prototype/assets/cutins) に置く
2. `data/cutins.json` の `imagePath` を画像ファイル名に合わせる
3. 必要なら `accentColor` や `durationMs` を調整する

推奨サイズは `480x180` 前後です。透明 PNG にしておくと後で見栄えを調整しやすいです。

- オープニング後に `Stoneford Outpost` の街ハブへ移動すること

- 街で `TALK` / `NEXT NPC` により NPC 会話を確認できること
- `SHOP` から `BUY` で所持金を消費して商品を購入できること
- `INN` で所持金を消費して味方 HP / MP が全回復すること
- `CHAPTER` から Chapter 1 を開始し、勝利後に Chapter 2 が解放されること
- Chapter 20 クリア後に最終エンディングシーンが流れること
- `DUNGEON` から9種類のルートを順に選び、ルート別シナリオ後に戦闘へ入れること
- ダンジョン一覧が5件ずつスクロールし、選択中の番号とルート名が表示されること
- `Old Road Skirmish` は小マップ・敵少、`Pinewood Ambush` は中マップ・敵並、`Sunken Ruins` は大マップ・敵多になること
- `MOVE` で青い移動範囲が出ること
- `MOVE` 中に移動先へカーソルを置くと経路ラインと手順番号が出ること
- 弓は 2-4 マス、剣は隣接、槍は 1-2 マスの射程になること
- `Mira` の `MAGIC Spark` は空マス中心でも範囲プレビューが出ること
- 森タイル上の敵には防御・回避補正が入ること
- 毒沼タイル上で行動終了すると HP が減ること
- 弓などの対象選択時に射線が表示されること
- 敵弓兵と術者が、近接敵より距離を取りやすいこと
- `Gloom Acolyte` が負傷した敵を回復すること
- `Iron Voss` が範囲攻撃と撃破可能な対象を優先しやすいこと
- ダメージ、回復、ミス時にマップ上へポップアップが出ること

- `SAVE` 後に移動してから `LOAD` すると状態が戻ること
- 勝利・敗北時にリザルトが表示されること

- 攻撃または物理スキルを使うと PARTY 画面の武器熟練度 XP が増えること
- 武器熟練ランクが上がると PARTY 画面の `Rank Bonus` とステータスに反映されること
- `EQUIP ARMOR` / `EQUIP ACC` でステータスが変化すること
- PARTY 画面で次の武器・防具・アクセサリー候補のステータス差分が表示されること

## 技術選定メモ

本編化する場合の第一候補は Godot 4 です。Unity は 2D、UI、配布、アセット資産が強い一方で、個人・同人の小規模 2D RPG ではプロジェクトが重くなりやすく、ライセンスやエディタ運用の負担も大きめです。Godot は軽量で、TileMap、JSON/Resource データ管理、Windows エクスポート、オフライン配布との相性がよく、ソース管理もしやすいため、この企画に合います。

このリポジトリは現環境に Godot が入っていないため、まず HTML5 Canvas で戦闘仕様を検証するプロトタイプとして作っています。戦闘ロジックとデータを分けているので、後で Godot の `Resource` / `TileMapLayer` / シーン構成へ移植しやすい形です。
